# 回言 · Re:Play

[English](README.en.md)

回言（Re:Play）为 DSH 提供输入历史回翻与用户消息重试。仓库名和安装包名统一为 `dsh-replay`。

本文面向 `dsh-replay` 原生组件版，说明最新行为与使用方式；旧 `dsh-shuru` 的自建设置页说明不适用于本版本。

## 组件与语言

一个安装包包含两个原生 Cordis 组件：**输入历史**和**消息重试**。两者默认开启，可以在 DSH 的组件管理页分别启用或停用，互不依赖。

本版本没有自建设置页，只使用 DSH 原生组件开关。客户端通过宿主组件清单接口每秒同步一次启停状态，正常情况下开关约在 1 秒内生效（网络和清理耗时可能延长）；停用时会清理该功能实例，不只是隐藏按钮。不会读取、迁移或删除旧版保存在 `localStorage` 中的开关值，也不需要手动清理浏览器数据。

界面支持中文和英文，语言跟随 DSH，无需单独设置。

## 输入历史

- **仅当前会话**：历史按会话隔离，不跨会话共享。当前会话已发送的输入和旧用户消息都可作为历史来源，不把工具或运行时注入内容当作用户输入。
- **逐条回翻**：在输入框按 **↑** 浏览更早的输入，按 **↓** 返回较新的输入；越过最新一条后，恢复开始回翻前的草稿，包括引用内容。
- **保留原生编辑行为**：只有输入框为空或光标位于首行时，↑ 才尝试回翻；普通段落内的光标移动、输入法组合与宿主已消费的按键仍交给宿主。只有成功写回历史时才消费方向键。
- **定位文首**：写回历史后将光标定位到内容开头，便于继续按 ↑ 回翻或编辑；用户主动修改草稿时退出回翻状态。
- **旧消息逐页读取**：进入会话时读取已有用户消息，必要时通过 `loadOlder()` 补一页；回翻到最早已加载的条目后，仅在宿主表示还有更早消息（`hasMore`）时继续加载下一页。没有更多消息时不反复请求。
- **按需加载，不设默认条数上限**：原生组件逐页读取更早输入，不再因达到 100 或 2,000 条而停止回翻。不会在后台自动读取整个会话；内存随已加载历史与文本长度增长，停用组件时释放。能回翻的范围仍取决于 DSH 提供的会话记录。

历史保存在组件运行期间的内存中，不是独立的永久存档；旧输入能否回填取决于 DSH 可提供的会话消息。

## 消息重试

用户消息下方的操作行按时间、复制、重试的顺序显示。点击重试，将该消息的**文本**以 `queue` 模式作为新提问追加到当前会话。

- 不原地替换，不删除或修改原消息，也不重写已有回答。
- 只重新发送文本，不重复上传原消息中的图片或其他附件。
- 当前会话正在生成回答时，重试按钮不可点击。
- 发送失败时显示原因，不将失败当作成功。
- 停用消息重试组件后，撤销该组件的用户消息渲染接管，恢复 DSH 的宿主渲染；输入历史组件可以继续运行。

重试针对用户提问，也兼容部分来源标记缺失的旧用户消息；工具注入、运行时上下文和生成中的插话不提供重试。

## 安装与迁移

需要可用的 DSH 和 Node.js。支持从本地目录或 GitHub 仓库安装；这里不提供 npm 安装命令，也不表示已发布到 npm。

### 从旧版迁移

**先停用或卸载旧 `dsh-shuru`，再安装 `dsh-replay`。不要同时启用两个包**，否则可能发生快捷键与用户消息渲染注册冲突。

旧开关值不迁移；新包的两个原生组件默认开启。

### 从本地目录安装

```sh
git clone https://github.com/AutumnNazi/dsh-replay.git
cd dsh-replay
node scripts/build.mjs
```

在 DSH 的插件管理页选择从本地目录安装，选择克隆后的 `dsh-replay` 项目目录，并按 DSH 提示完成加载。

### 从 GitHub 仓库安装

在 DSH 的插件管理页选择从 GitHub 仓库安装，使用以下仓库地址，并按 DSH 提示完成安装：

```text
https://github.com/AutumnNazi/dsh-replay.git
```

## 开发与检查

在项目目录执行：

```sh
node scripts/build.mjs
node scripts/check.mjs
node --test
```

`build` 生成 `lib/` 客户端和入口产物；`check` 检查清单、补丁、构建产物与扩展面约束；`node --test` 运行自动测试。不要把仅修改 `src/` 当作已更新安装包。

## 更新如何生效

已加载的客户端 bundle 默认由 DSH 的 `client-hmr` 每 **500 ms** 轮询。重新构建后可等待更新通知；不必把每一次源码修改都当成必须完整重启。

首次安装，或修改包名、manifest、组件入口与补丁时，按 DSH 提示重新加载配置或重启。

若 bundle 更新没有生效，再尝试刷新界面并按宿主提示重载。
